# מיזוג „רשימת קניות” לתוך „לא לשכוח”

המטרה: אפליקציה אחת. הנושא „🛒 קניות בסופר” ב„לא לשכוח” מקבל את כל היכולות של רשימת הקניות, ונוסף נושא „🕯️ שבת”. אחרי שהמיזוג עובד, רשימת הקניות הנפרדת כבר לא נחוצה.

## איפה נמצא קוד המקור

- מאגר: `484963-ctrl/family-missions-android` (פרטי). אם הוא לא בסשן: `add_repo` (read) ואז `git clone --depth 1 https://github.com/484963-ctrl/family-missions-android /home/user/family-missions-android`.
- כל הקוד בקובץ אחד: `app/shopping/index.html`. תיעוד מלא: `.claude/skills/shopping-list/SKILL.md` באותו מאגר. כדאי לקרוא את שניהם לפני שמתחילים.
- גרסה חיה להשוואה: https://484963-ctrl.github.io/shopping/

## למה המיזוג פשוט יחסית

שתי האפליקציות בנויות באותה שיטה:

| | רשימת קניות | לא לשכוח |
|---|---|---|
| מבנה | HTML אחד, בלי שלב בנייה | אותו דבר (`www/index.html`) |
| שמירה | `localStorage` + `save()` עם `u` ו־`gone` | אותו דבר, אותם שמות פונקציות |
| סנכרון | Supabase, `shopping_get/put(p_code)` | Supabase (אותו פרויקט `opepjcatbfwtpymnnnvl`), `lo_lishkoach_get/put(p_code)` |
| מיזוג | `mergeDocs` – השינוי האחרון מנצח, מיון לפי מזהה, `stable()` | אותו עיקרון |
| טלפון | APK בעזרת Capacitor | אותו דבר |

לכן **לא מעתיקים את מנגנון הסנכרון**. משתמשים במה שכבר יש ב„לא לשכוח”, ומוסיפים רק שדות ופונקציות.

## מה מעבירים (לפי סדר)

### 1. כמות והוספה מהירה עם כמות
- במקור: `parse(text)` – „2 חלב”, „חלב 2”, „במבה x3” → `{name, qty}`.
- ביעד: משימה בנושא `super` מקבלת שדה `qty` (ברירת מחדל 1). בהוספה מהירה בתוך נושא קניות (`state.view === 'super'` או `'shabbat'`) מפעילים את `parse` לפני `parseQuick`.
- אותו שם פעמיים באותו נושא, כשהפריט עוד לא נקנה → מגדילים את `qty` ולא יוצרים משימה חדשה.
- בשורה: כפתור `×N` שמגדיל ב־1 בכל לחיצה, או `+` עדין כשהכמות 1 (מחזור עד 20).

### 2. קטגוריות לפי מעברים בסופר
- במקור: `CATS` (12 קטגוריות עם אימוג׳י ומילות מפתח, בסדר המעברים) ו־`guessCat(name)` עם זיכרון בחירה (`state.history`).
- ביעד: שדה `aisle` במשימות קניות. בתצוגת נושא קניות, מקבצים לפי `aisle` בסדר של `CATS`, ובתוך כל קבוצה מה שנקנה יורד לסוף.
- **לא לבלבל עם `cat`** של „לא לשכוח” (הנושא). `aisle` הוא תת־קבוצה בתוך הנושא.
- `state.history` (שם → מעבר) נכנס למסמך הסנכרון: ב־`mergeDocs` של היעד מוסיפים `history: {...b.history, ...a.history}`.

### 3. נושא „שבת” עם „שבת חדשה”
- במקור: `SHABBAT_DEFAULT` (18 פריטים) וכפתור „שבת חדשה” שמבטל סימונים בלי למחוק.
- ביעד: נושא חדש `{id: 'shabbat', icon: '🕯️', name: 'שבת'}`, שנוסף ב־`load()` כמו שנוסף `receipts` (ולא חוזר אם נמחק: בודקים `state.gone.shabbat`).
- פריטי ברירת המחדל נוצרים **עם מזהים קבועים** (`'0sh' + i`), אחרת כל מכשיר חדש יכפיל אותם בסנכרון.
- בתצוגת הנושא: כפתור „🕯️ שבת חדשה” (מבטל `done` לכל הפריטים, עם ביטול). אפשר גם לשקול חזרה שבועית אוטומטית ביום חמישי, אבל רק אם מבקשים את זה.

### 4. תמונות מוצרים (החלק הגדול)
מעתיקים כמעט כמו שהם, ומשנים את מקום השמירה:

| במקור | מה עושה |
|---|---|
| `PHOTOS`, `photoUrl`, `builtinPhoto` | כ־30 תמונות Unsplash מובנות (ירקות, פירות, חלב...) עם קרדיט |
| `photoFor(it, size)` | סדר עדיפות: תמונה שנבחרה ← מובנית (ירקות ופירות, מוצר במילה אחת) ← אוטומטית ← סמל |
| `fillAutoPhotos()` | חיפוש ברקע, אחד אחרי השני, כל 1.2 שניות, ניסיון חוזר אחרי יום |
| `getJson`, `findProducts`, `findWikidata`, `findWiki`, `findByBarcode`, `SOURCES`, `search` | חיפוש לפי שם או ברקוד, עם שורת אבחון לכל מקור |
| `openPhoto` + החלון `#photo` | צילום, גלריה, 🌐 גוגל תמונות, 📋 הדבקת תמונה או כתובת, ברקוד, גרירה ו־Ctrl+V במחשב |
| `shrink`, `usePhotoFile`, `usePhotoUrl` | הקטנה ל־240×240 JPEG ושמירה |

- **שמירה ביעד:** `state.photos` (שם המוצר → `src`) + `state.photoTimes` (שם → שעת שינוי), בתוך מסמך הסנכרון של „לא לשכוח”. מעתיקים את חלק התמונות מ־`mergeDocs` של המקור (לכל שם מנצח `photoTimes` הגבוה; `src` ריק = הוסר). התמונה לפי **שם** ולא לפי משימה, כדי שתחזור כשמוסיפים שוב „חלב תנובה”.
- `autoPhotos` נשאר מקומי בכל מכשיר (מפתח `lo-lishkoach-auto-photos-v1`), לא בסנכרון.
- „לא לשכוח” כבר יודע להקטין תמונות (קבלות, סמלי נושאים). אם יש שם פונקציה דומה – משתמשים בה ולא מכפילים.
- **הריבוע בשורה מופיע רק בנושאי קניות** (`super`, `shabbat`, ואולי `ali`), לא במשימות רגילות.
- ב־`sw.js` של היעד מוסיפים מטמון לתמונות מ־`images.unsplash.com`, `images.openfoodfacts.org`, `upload.wikimedia.org`, `commons.wikimedia.org`.

### 5. שיתוף רשימת קניות
- במקור: „שיתוף” שולח רק מה שעוד לא נקנה, מקובץ לפי מעברים, עם כמויות (Web Share, ואם אין – `wa.me`). מוסיפים כפתור כזה בתצוגת נושא קניות.

### 6. „ניקוי מה שנקנה”
- במקור: מוחק את מה שסומן, עם ביטול. ביעד, בנושא `super`: כפתור שמוחק את המשימות שבוצעו בנושא (מה שנמחק נרשם ב־`gone` דרך `save()`).

### 7. העברת הרשימה הקיימת (פעם אחת)
מי שכבר משתמש ברשימת הקניות לא צריך להקליד הכול מחדש:
- ב־⚙️ של „לא לשכוח”: „ייבוא מרשימת הקניות”, ומזינים את קוד הסנכרון של רשימת הקניות (12 תווים).
- קוראים `rpc('shopping_get', {p_code})` (אותו Supabase, הפונקציה כבר קיימת), ממירים:
  - `lists.general[]` → משימות `{cat: 'super', title: name, qty, aisle: cat, done}`
  - `lists.shabbat[]` → משימות `{cat: 'shabbat', ...}`
  - `photos` + `photoTimes` → `state.photos` + `state.photoTimes`
  - `history` → `state.history`
- מזהים חדשים (`uid()`), בלי לכפול שם שכבר קיים בנושא. אחר כך `save()`.
- אם הקוד לא נמצא – הודעה ברורה. לא מוחקים כלום מרשימת הקניות.

## דברים שאסור לשבור

- כל שינוי ברשימה עובר דרך `save()`, וכל שינוי תמונה דרך פונקציה שמעדכנת `photoTimes` ואז `scheduleSync()`.
- `itemKey` ביעד כבר כולל את כל השדות חוץ מ־`u`, אז `qty` ו־`aisle` נכנסים לבד לזיהוי שינוי.
- ההשוואה לפני העלאה לשרת חייבת להיות בלי תלות בסדר המפתחות (`stable`), אחרת המכשירים מעלים בלי הפסקה.
- הסנכרון של „לא לשכוח” עובד גם בלי אינטרנט (תור). לא להחליף אותו בזה של רשימת הקניות.
- להעלות `APP_VERSION` בראש `www/index.html`.

## בדיקה

אין גישה מהסביבה לאינטרנט החיצוני, ולכן בודקים עם Playwright ותשובות מדומות (בדיוק כמו בסקיל `shopping-list`):
1. `python3 -m http.server` מתוך `www`, Chromium ב־`/opt/pw-browsers/chromium`, `serviceWorkers: 'block'`.
2. מדמים תמונות (SVG), מקורות חיפוש (JSON עם `access-control-allow-origin: *`), ו־`rest/v1/rpc/*` (מאגר בזיכרון; גם `shopping_get` לבדיקת הייבוא).
3. תרחישים: הוספה עם כמות, אותו שם פעמיים, קיבוץ לפי מעברים, „שבת חדשה”, תמונה (מובנית, אוטומטית, הדבקה), ייבוא מקוד, ושני מכשירים מסונכרנים בלי העלאות מיותרות.
4. צילום מסך בגודל טלפון (390×844) ובגודל מחשב.
